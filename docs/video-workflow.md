# 可选：原声技术讲解视频

这条流程用于把真实 RPG 制作过程剪成技术讲解视频，不是 SDK 核心功能。仓库不包含用户原声、游戏录屏、截图、字体或音效，也不捆绑 GSAP/HyperFrames 的官方 Skill 正文。`skills/rpg-original-voice-video` 可独立安装；视频工具和媒体均由使用者提供。

## 原稿与原声优先

先保存原录音的文件哈希、格式、采样率、容器时长和解码时长。源文件不改；需要转格式或调节响度时产生派生文件并记录处理。整段原音不剪、语句不重排、不变速、不换 TTS，不删除停顿，也不擅自改原稿。字幕采用用户原文，ASR 只辅助找时间，不用识别错误替换文字。

如果录音超过目标平台时长，先指出冲突，不能为了“二分钟内”自行删句。公开发布代码也不意味着授权公开某个人的声音；视频上传另行确认。

## 每一个镜头都回答一句话

先做细粒度剪辑表，再制作动画。推荐字段：

| 字段 | 示例 |
| --- | --- |
| 全局时间 | `00:38.100 -> 00:41.150` |
| 口播 | 原稿中正在说的那一句，不改写 |
| 素材时间 | `occlusion.mp4` 的 `3.300 -> 6.350` |
| 画面目的 | 人物从树前走到树后，观察脚点排序 |
| 裁切/运镜 | 包含人物与树根的固定证明窗口 |
| 屏幕文字 | 实际算法名称或必要标注 |
| 转场 | 保留同源时钟，切换覆盖层，不重置相机 |
| 音效 | 峰值对准“进入遮挡”时刻，低增益短包络 |
| 验收 | 进入遮挡前后都可见，字幕没有挡住证明区 |

素材优先使用真实游戏和实际 SDK 结果。展示失败概念时可以用明确标注的“问题示意”，但不能把演示性错位伪装成线上测出的 bug。不要伪造“已开源”链接、自动生成成功率、token 节省比例或测试数量。

最大矩形、路径、碰撞和遮挡演示要给观众看够完整过程。描述一个矩形的大小时必须看见其四边；碰撞演示要看见移动接近和阻挡；遮挡演示要看见人物在前和在后的两种状态。术语与镜头相配，不是大字覆盖证据。

## GSAP 运镜：共享相机与全局时钟

GSAP 可用于确定性的相机、文字和遮罩编排。适配器负责图片/视频/音频解码与播放，GSAP 不负责媒体时钟。以一条暂停时间轴从全局时间求状态；禁止按每个镜头重新启动动画、使用随机数或依赖真实时间。

下面是局部模式示意，使用者需要接入自己的 DOM、播放器和渲染器：

```js
const timeline = gsap.timeline({ paused: true });
timeline.set(camera, { scale: 1, xPercent: 0, yPercent: 0 }, 0);
timeline.set(incoming, { opacity: 0 }, 0);
timeline.set(outgoing, { opacity: 1 }, 0);
timeline.fromTo(camera,
  { scale: 1, xPercent: 0, yPercent: 0 },
  { scale: 1.15, xPercent: 4, yPercent: -2,
    duration: 2, ease: "power2.inOut", immediateRender: false },
  0
);

// 遮罩揭示时先保持上一层完整，新层完全覆盖后再退出上一层。
timeline.set(incoming, { opacity: 1 }, 8);
timeline.fromTo(incoming,
  { clipPath: "inset(0 100% 0 0)" },
  { clipPath: "inset(0 0% 0 0)", duration: 0.35,
    ease: "power2.inOut", immediateRender: false },
  8
);
timeline.set(outgoing, { opacity: 0 }, 8.35);
```

每次 seek 应直接得到目标时刻状态，包括倒退 seek。相机窗口与定时素材层分离；同一段素材的微剪辑共享相机轨迹，不在切点恢复为 1 倍。证明窗口适当保持稳定，不要在观众看路径时继续剧烈摇移。

如果两个半透明层同时淡出/淡入，合成结果可能变暗或露底。遮罩转场需要明确上一层退场的时刻；同源证明镜头可以不做双重淡化。分别检查切点前、切点、切点后，并看实际导出，不只检查浏览器预览。

## 音效不是越多越技术

人声是主轨，背景音乐可选。为每个音效记录来源/许可、开始点、音效内部峰值偏移、目标视觉事件、音量、起落包络。音效文件开头可能是空白或渐强，应该让实际峰值而不是文件起点对齐事件。

检查工具的音量自动化语义：有的包络是绝对音量，不是“在静态音量上再乘一次”。忽略这点可能让原本低增益的 whoosh 突然变成满音量。尽量把宽频冲击放在句间或语义重点之后，保护辅音、术语和句尾。

响度与 true peak 测量证明电平是否合理，不证明内容没有被剪掉。还需解码原音与最终音频，在开头、中间、末尾的有声区间比较对齐，检查无逐渐漂移。AAC 编码填充可能造成几毫秒差异，需记录而不是把容器数字当作删除语句的证据。音效会影响相关度；必要时检查语音频段和音效密集区。没有实际试听工具时不写“已听过”。

## HyperFrames 是可选适配器

已经安装 HyperFrames 时，先读取该版本的入口、composition、keyframe、audio 和 CLI 合同，使用其原生全局时钟与媒体管理。没有安装时可以使用用户选择的其他视频工具，做到等价的完整原声、确定性画面和导出验收。不要在地图生成命令里强制安装视频服务，也不要复刻未公开的 vendor API。

同样，官方 GSAP Skill 应从官方来源安装，而不是复制进本仓库。工具版本和使用到的插件许可单独记录。

## 导出失败时不要改内容来绕过

先确认报错、渲染进度、内存或浏览器日志，再决定降低并发或使用渲染器支持的分段捕获。每段仍按原全局 `frameIndex/fps` seek，并保持原素材时间。拼接不丢帧、不重复帧；完整人声最后只混合一次。分段释放资源是工程处理，不是获准剪掉录音。

设定有限重试，保留可编辑工程和此前已批准的版本。不随便结束无关浏览器/游戏，不把预览可播放当成导出成功。

## 最终交付检查

1. 输出文件真实存在，完整解码，无损坏、缺段或黑帧。
2. 分辨率、帧率、编码、时长和总帧数符合实际记录。
3. 从成片抽取关键帧、切点附近帧和运动帧，检查素材、证明窗口、字幕安全区与 alpha。
4. 检查原声完整区间和多个时间窗对齐，无变速或删改。
5. 检查实际响度、true peak 和人声清晰度，说明测量与人工试听的区别。
6. 提供成片、逐镜头表、音效表和可编辑工程。新版本另存，旧版保留。

这条流程保留的是作者原话。字幕和画面不能额外杜撰技术能力；改口播、发布视频或更换素材来源需要新的明确选择。
